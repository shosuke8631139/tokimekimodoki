# 鹿児島お宝再生物件ウォッチャー (akiya-watcher)

鹿児島県(+都城市)の空き家バンク等から「売主側の事情で安く手放される家」を
継続監視し、**値下げ・有望新着の瞬間だけ**通知するツールです。

## 運用モデル: 「何もない日は何も来ない」

毎朝のチェック作業を自動化するのではなく、チェック作業そのものを無くす:

| 層 | 頻度 | 中身 |
|---|---|---|
| 即時通知 | 数時間おきの巡回で発火 | 値下げは原則すべて・新着はスコア閾値以上のみ。土地のみ(山林・原野・更地)は鳴らさない。倒壊級の記載は閾値を上げる |
| 週次ダイジェスト | 週1回 | 通知から漏れた掘り出し候補+指値候補のまとめ |
| 台帳レポート(HTML) | 巡回ごとに更新 | 全物件をスコア順に「落とさず」掲載。通知が来た時に開く |

**二層構造が核**: フィルタするのは割り込み(通知)であってデータではない。
「絞りすぎて見逃す」リスクは台帳側が担保し、通知は鳴ったら必ず見る価値がある
状態を保つ。

## 指値候補リスト — 値下げを「待つ」のではなく「起こす」

掲載90日超・値下げ履歴ありの物件は、売主が譲歩し始めているサイン。
台帳レポートの「🎯指値候補」セクションと週次ダイジェストに自動掲載され、
こちらから大幅指値を入れる攻めの候補として使う。

## ⚠️ 最初に必ず読むこと(法務・運用上の注意)

1. **商用ポータル(楽待・健美家・アットホーム・SUUMO 等)は利用規約で
   自動収集(スクレイピング)を禁止しています。** 本ツールの対象にしないで
   ください。規約違反はアカウント停止や法的リスクにつながります。
   これらのサイトは公式の「新着メール通知」機能で条件保存するのが正攻法です。
2. 対象にしてよいのは、**各自治体の空き家バンク**など公共性の高い情報源で、
   かつ robots.txt と利用規約が自動アクセスを禁じていないもの。本ツールは
   robots.txt を自動チェックし、同一ホストへのアクセス間隔を10秒以上空けます。
   実行頻度も1日数回程度(cron 例参照)に留めてください。
3. **LINE Notify は2025年3月末にサービス終了**したため、通知は
   Slack Incoming Webhook を使います。LINE に送りたい場合は
   LINE Messaging API 用の Notifier を `notify.py` に追加してください。

## 全体設計

```
config.yaml ─┐
             ▼
┌─────────────────────────────────────────────────────┐
│ main.py (cron で定期実行)                            │
│                                                     │
│  scrapers/   … 情報源ごとのアダプタ (取得・正規化)    │
│    base.py         robots.txt 尊重・レート制限        │
│    generic_html.py 設定駆動の汎用HTMLパーサ           │
│    demo.py         ローカルJSON (動作確認用)          │
│        │  list[Listing]  (共通データモデル)           │
│        ▼                                            │
│  criteria.py … 判定 (価格/駐車/延床/間取り/水洗/KW)   │
│        │  Judgement (matched, score, 理由)           │
│        ▼                                            │
│  storage.py  … SQLite で既知物件を記録し差分検知      │
│        │  Diff ("new" / "changed")                   │
│        ▼                                            │
│  notify.py   … Slack Webhook へ整形メッセージ送信     │
└─────────────────────────────────────────────────────┘
```

設計のポイント:

- **アダプタ方式**: サイト構造の違いは scrapers/ に閉じ込め、判定・通知は
  共通の `Listing` モデルだけを扱う。自治体空き家バンクの多くは
  「一覧ページ+物件カード」の同型構造なので、`generic_html` タイプなら
  **コードを書かずに config.yaml のセレクタ設定だけで情報源を追加**できる。
- **判定は純関数**: 「198万円」「並列2台可」「簡易水洗」等の表記揺れを
  正規化するパーサをすべて `criteria.py` に集約し、単体テストで担保。
- **差分検知**: SQLite に uid と内容ハッシュを保存。初見→「新着」、
  価格・本文変化→「掲載変更(旧価格→新価格)」として通知。再掲載の重複通知なし。

## ライブラリ選定

| 用途 | 採用 | 理由 |
|---|---|---|
| HTTP取得 | requests | 定番。セッション/タイムアウト管理が簡潔 |
| HTML解析 | BeautifulSoup4 | 自治体サイト程度の静的HTMLには十分 |
| 設定 | PyYAML | 条件・セレクタを非エンジニアでも編集可能に |
| 保存 | sqlite3 (標準) | 依存追加なしで差分検知に十分 |
| 通知 | urllib (標準) | Webhook POST だけなので依存不要 |
| テスト | pytest | パーサ・判定・E2E の回帰防止 |

JSレンダリングが必要なサイトが出てきたら Playwright を追加する(MVPでは不使用)。

## セットアップ

```bash
cd akiya-watcher
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# 動作確認 (ネットワーク不要のデモデータで判定ロジックを確認)
python -m akiya_watcher.main --config config.yaml --dry-run

# 本実行 (Slack通知。未設定なら標準出力に出る)
export SLACK_WEBHOOK_URL="https://hooks.slack.com/services/XXX/YYY/ZZZ"
python -m akiya_watcher.main --config config.yaml
```

テスト:

```bash
pytest
```

## 定期実行 (cron 例)

```cron
# 巡回: 9〜19時に3時間おき (空き家バンクの更新は営業時間内なので夜間は不要)
0 9,12,15,18 * * * cd /path/to/akiya-watcher && ./.venv/bin/python -m akiya_watcher.main --config config.yaml --report data/report.html >> data/watch.log 2>&1
# 週次ダイジェスト: 日曜朝8時
0 8 * * 0 cd /path/to/akiya-watcher && ./.venv/bin/python -m akiya_watcher.main --config config.yaml --digest >> data/watch.log 2>&1
```

## クラウド常駐モード (パソコン不要・推奨)

`.github/workflows/akiya-patrol.yml` / `akiya-digest.yml` により、GitHub Actions が
JST 9/12/15/18時の巡回と日曜朝のダイジェストを自動実行する。PCの電源は不要。

有効化の3条件:
1. このブランチを main にマージする (スケジュール実行は既定ブランチのみ)
2. リポジトリ Settings > Secrets and variables > Actions に
   `GMAIL_APP_PASSWORD` を登録する
3. `config.yaml` の `notify.email` と `gmail_portal_mail` を自分のGmailに設定する

巡回結果 (listings.db / report.html) はリポジトリにコミットされ履歴が残る。
クラウドIPがブロックされるソースが出た場合は、そのソースだけ自宅PC実行に
切り替える (同じDBを共有できるので併用可)。

## Gmail連携のセットアップ (楽待・アットホーム・SUUMO等のカバー)

スクレイピング禁止のポータルは、公式の通知メールを解析する方式でカバーする。
自分宛てのメールを自分で処理するだけなので規約違反にならない。

1. **ポータル側**: 楽待・アットホーム・SUUMO等で会員登録し、検索条件を保存して
   「新着メール通知」をONにする。気になる物件は「お気に入り」に入れて
   更新通知もONにする(お気に入りの価格変更メール = 値下げ検知の入口)。
2. **Gmail側**: フィルタを作成し、各ポータルからの通知メールにラベル
   `bukken` を付ける(ラベル名は半角英数推奨。日本語はIMAPで文字化けしやすい)。
3. **Googleアカウント**: 2段階認証を有効化 → [アプリパスワード](https://myaccount.google.com/apppasswords)
   を発行 → 実行環境の環境変数に設定:
   ```bash
   export GMAIL_APP_PASSWORD="xxxx xxxx xxxx xxxx"
   ```
   ※アプリパスワードは通常のパスワードとは別物。config や git には書かないこと。
4. **config.yaml**: `gmail_portal_mail` ソースの `username` を自分のアドレスに
   変えて `enabled: true` にする。

メールから抽出された物件は空き家バンクと同じスコアリング・差分検知に合流する。
同じ物件の価格が変わったメールが届けば、値下げとして即時通知が鳴る。
メール本文の形式はポータルごとに違うため、汎用パーサ(リンク+周辺テキスト)で
拾う設計にしてある。実際のメールが届き始めて取りこぼしがあれば、そのメールを
サンプルにポータル別パーサを追加する。

## 情報源の追加方法

1. 対象自治体の空き家バンク一覧ページを開き、**利用規約と robots.txt を確認**。
2. ブラウザの開発者ツールで物件カードの CSS セレクタを調べる。
3. `config.yaml` の `sources` に `generic_html` タイプで追記(コメント例あり)。
4. `--dry-run` で取得・判定結果を確認してから有効化。

一覧ページに詳細情報(トイレ形式・駐車台数など)が無いサイトでは、判定は
「不明(要確認)」扱いで通知されるので、通知を起点に手動で詳細確認する運用を
想定しています(詳細ページの追撃取得は次フェーズ)。

## 判定条件 (config.yaml の criteria)

- 掲載価格 200万円以下(価格「応相談」等は指値候補として通知に含める)
- 駐車2台以上(台数記載がなければ敷地200㎡以上でフォールバック合格)
- 延床80㎡以上 **または** 4LDK/4DK以上
- 水洗トイレ(公共下水・浄化槽)。「簡易水洗」は汲み取り扱いで除外
- お宝キーワード: 残置物/現状渡し/現状有姿/未片付け/家具/家財/要補修/古家 等
  → 合致数がスコアに加算され、通知の `score` で優先度が分かる
- 優先エリア(鹿児島市・霧島市・薩摩川内市・鹿屋市など)はスコア加点

## 次フェーズ候補 (MVP範囲外)

- 物件詳細ページの追撃取得(トイレ・駐車台数の精度向上)
- 全国版空き家バンク(国交省事業)への対応アダプタ
- 固定資産税評価額・再建築可否・ハザードマップ照合の半自動化
- LINE Messaging API 通知
