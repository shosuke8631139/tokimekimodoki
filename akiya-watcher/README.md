# 鹿児島お宝再生物件ウォッチャー (akiya-watcher)

鹿児島県内の空き家バンク等から「残置物あり・現状渡し」の格安再生向き物件を
定期収集し、条件判定して Slack に通知する監視ツールの MVP です。

## ⚠️ 最初に必ず読むこと(法務・運用上の注意)

1. **商用ポータル(楽待・健美家・アットホーム・SUUMO 等)は利用規約で
   自動収集(スクレイピング)を禁止しています。** 本ツールの対象にしないで
   ください。規約違反はアカウント停止や法的リスクにつながります。
   これらのサイトは公式の「新着メール通知」機能で条件保存するのが正攻法です。
2. 対象にしてよいのは、**各自治体の空き家バンク**など公共性の高い情報源で、
   かつ robots.txt と利用規約が自動アクセスを禁じていないもの。本ツールは
   robots.txt を自動チェックし、同一ホストへのアクセス間隔を10秒以上空けます。
   実行頻度も1日数回程度(cron 例参照)に留めてください。
3. **LINE Notify は2025年3月末にサービス終了**したため、通知は
   Slack Incoming Webhook を使います。LINE に送りたい場合は
   LINE Messaging API 用の Notifier を `notify.py` に追加してください。

## 全体設計

```
config.yaml ─┐
             ▼
┌─────────────────────────────────────────────────────┐
│ main.py (cron で定期実行)                            │
│                                                     │
│  scrapers/   … 情報源ごとのアダプタ (取得・正規化)    │
│    base.py         robots.txt 尊重・レート制限        │
│    generic_html.py 設定駆動の汎用HTMLパーサ           │
│    demo.py         ローカルJSON (動作確認用)          │
│        │  list[Listing]  (共通データモデル)           │
│        ▼                                            │
│  criteria.py … 判定 (価格/駐車/延床/間取り/水洗/KW)   │
│        │  Judgement (matched, score, 理由)           │
│        ▼                                            │
│  storage.py  … SQLite で既知物件を記録し差分検知      │
│        │  Diff ("new" / "changed")                   │
│        ▼                                            │
│  notify.py   … Slack Webhook へ整形メッセージ送信     │
└─────────────────────────────────────────────────────┘
```

設計のポイント:

- **アダプタ方式**: サイト構造の違いは scrapers/ に閉じ込め、判定・通知は
  共通の `Listing` モデルだけを扱う。自治体空き家バンクの多くは
  「一覧ページ+物件カード」の同型構造なので、`generic_html` タイプなら
  **コードを書かずに config.yaml のセレクタ設定だけで情報源を追加**できる。
- **判定は純関数**: 「198万円」「並列2台可」「簡易水洗」等の表記揺れを
  正規化するパーサをすべて `criteria.py` に集約し、単体テストで担保。
- **差分検知**: SQLite に uid と内容ハッシュを保存。初見→「新着」、
  価格・本文変化→「掲載変更(旧価格→新価格)」として通知。再掲載の重複通知なし。

## ライブラリ選定

| 用途 | 採用 | 理由 |
|---|---|---|
| HTTP取得 | requests | 定番。セッション/タイムアウト管理が簡潔 |
| HTML解析 | BeautifulSoup4 | 自治体サイト程度の静的HTMLには十分 |
| 設定 | PyYAML | 条件・セレクタを非エンジニアでも編集可能に |
| 保存 | sqlite3 (標準) | 依存追加なしで差分検知に十分 |
| 通知 | urllib (標準) | Webhook POST だけなので依存不要 |
| テスト | pytest | パーサ・判定・E2E の回帰防止 |

JSレンダリングが必要なサイトが出てきたら Playwright を追加する(MVPでは不使用)。

## セットアップ

```bash
cd akiya-watcher
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# 動作確認 (ネットワーク不要のデモデータで判定ロジックを確認)
python -m akiya_watcher.main --config config.yaml --dry-run

# 本実行 (Slack通知。未設定なら標準出力に出る)
export SLACK_WEBHOOK_URL="https://hooks.slack.com/services/XXX/YYY/ZZZ"
python -m akiya_watcher.main --config config.yaml
```

テスト:

```bash
pytest
```

## 定期実行 (cron 例: 8時・13時・19時の1日3回)

```cron
0 8,13,19 * * * cd /path/to/akiya-watcher && ./.venv/bin/python -m akiya_watcher.main --config config.yaml >> data/watch.log 2>&1
```

## 情報源の追加方法

1. 対象自治体の空き家バンク一覧ページを開き、**利用規約と robots.txt を確認**。
2. ブラウザの開発者ツールで物件カードの CSS セレクタを調べる。
3. `config.yaml` の `sources` に `generic_html` タイプで追記(コメント例あり)。
4. `--dry-run` で取得・判定結果を確認してから有効化。

一覧ページに詳細情報(トイレ形式・駐車台数など)が無いサイトでは、判定は
「不明(要確認)」扱いで通知されるので、通知を起点に手動で詳細確認する運用を
想定しています(詳細ページの追撃取得は次フェーズ)。

## 判定条件 (config.yaml の criteria)

- 掲載価格 200万円以下(価格「応相談」等は指値候補として通知に含める)
- 駐車2台以上(台数記載がなければ敷地200㎡以上でフォールバック合格)
- 延床80㎡以上 **または** 4LDK/4DK以上
- 水洗トイレ(公共下水・浄化槽)。「簡易水洗」は汲み取り扱いで除外
- お宝キーワード: 残置物/現状渡し/現状有姿/未片付け/家具/家財/要補修/古家 等
  → 合致数がスコアに加算され、通知の `score` で優先度が分かる
- 優先エリア(鹿児島市・霧島市・薩摩川内市・鹿屋市など)はスコア加点

## 次フェーズ候補 (MVP範囲外)

- 物件詳細ページの追撃取得(トイレ・駐車台数の精度向上)
- 全国版空き家バンク(国交省事業)への対応アダプタ
- 固定資産税評価額・再建築可否・ハザードマップ照合の半自動化
- LINE Messaging API 通知
