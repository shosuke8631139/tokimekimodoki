# 本番反映手順書 — 番人の仕事の完全な手順

この手順どおりにやれば、誰(どのAIツール・人間)でも本番反映ができる。
Claudeが番人としてやってきた作業をそのまま文書化したもの。

## 前提の理解(これだけは頭に入れる)

- 巡回はGitHub Actions(クラウド)で毎日自動実行される。**どのAIも止まっても
  メールは届き続ける**。壊せるのは「本流ブランチに悪い変更を入れた時」だけ
- 本流 = `claude/inspiring-gates-bq5fai`。ここへのマージ=本番反映
- 安全網は二重にある:
  1. **機械の番人(akiya-tests.yml)**: 全pushで自動テスト。GitHubの
     コミット一覧で緑✅か赤❌が見える。赤いブランチは絶対にマージしない
  2. **死活監視**: 定期便は1日1通必ず届く設計。**メールが来ない日=何かが
     壊れた日**。その日はこの手順書の「巻き戻し」を実行する

## 反映手順(1件の作業ブランチを本番に入れる)

1. **検品**: 作業ブランチのdiffを読む。見るのは
   - テストが増えている/更新されているか(コードだけの変更は疑う)
   - config.yaml のユーザー決定値(価格上限300万等)を変えていないか
   - 個人情報・Secretsが入っていないか
2. **機械の番人が緑か確認**: GitHubのブランチページで最新コミットに
   緑✅が付いているか見る。またはCLIで:
   `gh run list --branch <作業ブランチ> --workflow akiya-tests.yml --limit 1`
3. **マージ**:
   ```
   git fetch origin claude/inspiring-gates-bq5fai
   git checkout -B honryu origin/claude/inspiring-gates-bq5fai
   git merge --no-ff <作業ブランチ>
   git push origin honryu:claude/inspiring-gates-bq5fai
   ```
4. **巡回を手動実行して確認**:
   ```
   gh workflow run akiya-patrol.yml --ref claude/inspiring-gates-bq5fai
   gh run watch    (完了まで待つ。3〜5分)
   gh run view --log | grep "メール送信完了"   (Windowsは findstr)
   ```
   「メール送信完了」が出れば反映成功。メールの見た目確認だけしたい時は
   `-f preview_bundle=true` を付ける(定期便の1日1回ガードに触れない)
5. **NEXT.mdを更新**: 何をやったか・学びを追記してcommit+push
   (これが次のセッション・次のAIへの引き継ぎになる)

## 巻き戻し(メールが来ない/巡回が赤くなった時)

1. GitHub Actionsで akiya-patrol の失敗ログを読む(エラーの正体を掴む)
2. 急ぐ時は疑わしいマージを打ち消す:
   ```
   git checkout -B honryu origin/claude/inspiring-gates-bq5fai
   git revert -m 1 <マージコミットのハッシュ>
   git push origin honryu:claude/inspiring-gates-bq5fai
   ```
3. 巡回を手動実行して「メール送信完了」が戻ることを確認
4. 原因究明はその後でよい(まず本番を green に戻す)

## 番人の心得

- 赤いテストのマージ・検品なしのマージは、どんなに急いでいてもしない
- 「実行した」の報告は信じず、GitHub上の事実(コミット・✅・ログ)で確認する
- 迷ったら反映せず、ユーザーに選択肢を添えて相談する
